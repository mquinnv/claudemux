# Haiku-generated terminal tab title — design

**Date:** 2026-07-15
**Status:** proposed

## Goal

Give each claudemux session a short, descriptive terminal-tab title generated by the same Haiku summarizer that already produces the status-pane lines — so a row of tabs reads like a list of what each session is doing, not "tmux, tmux, tmux."

## Decisions (from brainstorming)

1. **A dedicated short field**, not a truncated `topic`. Haiku already emits `topic` (the session's goal, up to ~60 chars) and `now` (the current step). Add a third field, `tab`: a 2–4 word label sized for a narrow tab (e.g. `crm bundling`). A tab is not a truncated sentence.
2. **Delivered by renaming the tmux window.** `claudemux-head` runs `tmux rename-window` with the title; the launcher enables `set-titles on` so tmux propagates the window name to the terminal tab. Simplest and most reliable. Accepted side effect: the title also becomes the window label in the tmux status bar — fine for these single-window sessions.

## Components

### 1. Summarizer (`cmd/claudemux-head/summary.go`)

- `Summary` gains `Tab string \`json:"tab"\``.
- The `summarize` tool's input schema gains a `tab` property (required, alongside `topic`/`now`).
- The system prompt gains a `tab` instruction: **2–4 words, lowercase, ≤ 24 characters, no punctuation** — the shortest phrase that says which project/task this is. Derive it from the same evidence as `topic` (durable — the goal, not the current detour), so the tab stays stable while `now` churns.
- `placeholderLine` already guards `topic`/`now`; apply it to `tab` too, so a `<UNKNOWN>`-style non-answer doesn't become a tab title. If `tab` is a placeholder, the whole summary is rejected and the pane keeps its prior title (same fallback path as today).

### 2. Applying the title (`cmd/claudemux-head/tui.go`)

- When a summary lands and `Tab` is non-empty, run `tmux rename-window -t "$TMUX_PANE" <tab>` for the pane's own window (the model already holds `selfPane` from `TMUX_PANE`).
- Fire-and-forget with a hard timeout, off the render loop, exactly like the existing `tmux list-panes` poll in `panemap.go` — a wedged tmux server must never block or crash the TUI. No error surfaced; a failed rename just leaves the previous title.
- Only when `TMUX_PANE` is set (running inside tmux). Outside tmux it is a silent no-op.

### 3. Launcher (`bin/claudemux`)

At session creation, alongside the existing `tmux set status-style`:

```sh
tmux set -t "$session_name" set-titles on
tmux set -t "$session_name" set-titles-string '#W'   # tab shows the window name
```

Self-contained: the user needs no `~/.tmux.conf` change, consistent with the tool's zero-config stance. `#W` makes the terminal title track the window name that `claudemux-head` sets.

### 4. Config toggle (`cmd/claudemux-head/config.go`)

Auto-renaming a user's tmux window is more invasive than drawing a status line, so it gets an explicit off-switch:

- `SummaryConfig` gains `TabTitle bool \`yaml:"tab_title"\``, **default true**.
- When false, `claudemux-head` still shows the status-pane summary but never renames the window. The `tab` field is still generated (it is one tool call); it is simply not applied.
- Independent of `summary.enabled`: `enabled: false` already disables the whole summarizer (no tab either); `tab_title: false` keeps summaries but leaves the window/tab alone.

## Testing

- `summary_test.go`: the parsed `Summary` includes `tab`; a placeholder `tab` is rejected like a placeholder `topic`; the `tab` instruction is present in the system prompt.
- `config_test.go`: `tab_title` defaults to true; `tab_title: false` loads as false; a partial file setting only `tab_title` leaves other summary defaults intact.
- `tui_test.go`: a landed summary with `TabTitle` true and `TMUX_PANE` set produces the rename command (test the command-builder, not a live tmux); with `TabTitle` false, no rename; with `TMUX_PANE` unset, no rename.
- Launcher: `bash -n` + `shellcheck`; the two `tmux set` lines are added and don't disturb the existing layout logic.

## README

Extend the **Appearance** / **tmux notes** sections: the tab title is Haiku-generated and updates as the session's focus settles; it also appears as the tmux window label; `summary.tab_title: false` turns it off; it needs no tmux config (claudemux sets `set-titles` itself); and outside tmux or iTerm it degrades to nothing.

## Out of scope

- Per-terminal title escape sequences (OSC 0/1/2) or tmux passthrough — the `set-titles`/`rename-window` path is simpler and needs no `allow-passthrough`.
- Making the tab title independent of the tmux status-bar window label (that was the rejected alternative mechanism).
- Icon/emoji in the title.
